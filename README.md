# Sample Internal Developer Platform (IDP)

A small, runnable platform that shows the main ideas of platform engineering on your laptop:

| Capability | Tool | Where |
|---|---|---|
| Infrastructure | kind (Kubernetes in Docker) | `cluster/` |
| GitOps delivery | Argo CD (app-of-apps) | `gitops/` |
| Ingress | ingress-nginx | `gitops/platform/ingress-nginx.yaml` |
| Observability | kube-prometheus-stack (Prometheus + Grafana) | `gitops/platform/monitoring.yaml` |
| Guardrails | Kyverno policies | `policies/` |
| Golden path | Service template + scaffolder | `templates/`, `scripts/new-service.sh` |
| CI | GitHub Actions (test → build → bump image tag) | `templates/python-service/.github/workflows/` |

```
 developer ──▶ make new-service NAME=payments
                     │  (copies golden-path template)
                     ▼
               git push ──▶ CI: test, build image, bump tag in values.yaml
                                        │
                                        ▼
          Argo CD watches gitops/ ──▶ syncs to cluster
                                        │
     ┌──────────────┬──────────────┬────┴─────────┐
  ingress-nginx  monitoring     Kyverno      your services
                 (Grafana)   (blocks bad YAML)  (/apps)
```

## Prerequisites
Docker, `kind`, `kubectl`, `helm` (v3). Roughly 4 CPU / 8 GB RAM for Docker.

## Quick start
```bash
# 1. Push this folder to your own GitHub repo, then point Argo CD at it:
export REPO_URL=https://github.com/<you>/sample-platform.git
make repo-url            # rewrites the repo URL in gitops/ manifests

make up                  # creates the kind cluster + installs Argo CD + app-of-apps
make status              # watch platform components come up
make argocd-ui           # https://localhost:8080  (user: admin, password printed)
make grafana-ui          # http://localhost:3000   (admin / prom-operator)

make local-image NAME=hello      # build the sample service image into the cluster
curl http://hello.localtest.me/  # *.localtest.me resolves to 127.0.0.1

make new-service NAME=payments   # scaffold a new service from the golden path
git add . && git commit -m "add payments" && git push   # Argo CD deploys it

make down                # delete everything
```

## Repo layout
```
cluster/kind-config.yaml        local cluster (ports 80/443 mapped to ingress)
gitops/bootstrap/root-app.yaml  Argo CD "app of apps" – the single entry point
gitops/platform/*.yaml          platform components (one Argo CD Application each)
gitops/apps/*.yaml              tenant services (generated by the scaffolder)
services/hello/                 a sample service already created from the template
policies/*.yaml                 Kyverno ClusterPolicies (the guardrails)
templates/python-service/       the golden path: app + Dockerfile + Helm chart + CI
scripts/                        bootstrap and scaffolding scripts
docs/learning-path.md           exercises to grow this into a real platform
```

## Platform principles shown here
1. **Everything in Git** – the cluster's desired state lives in `gitops/`; nobody runs `kubectl apply` by hand.
2. **Self-service** – a developer gets a deployable, monitored service with one command.
3. **Paved road, not a cage** – the template makes the right thing easy; Kyverno policies catch the wrong thing.
4. **Platform as a product** – read `docs/learning-path.md` for how to measure and improve it.
